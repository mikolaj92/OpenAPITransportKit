# OpenAPITransportKit

Alternative `ClientTransport` implementations for clients generated by
`swift-openapi-generator`.

OpenAPITransportKit swaps the source of HTTP responses without changing generated
client code. The generated client still owns request serialization, response
deserialization, status handling, and generated DTO mapping.

This package is not a test framework, not a mock server, and not an app
architecture layer. `ClientTransport` is the integration point.

## Requirements

- Swift 6.3 or newer.
- `OpenAPIRuntime` 1.12.0 or newer.
- `HTTPTypes` 1.5.1 or newer.

The package targets the latest Swift toolchain only. Older Swift versions are
not supported. The core runtime is platform-neutral and avoids UI frameworks,
server frameworks, and Apple-only APIs.

`swift-openapi-generator` is used only by the generated-client integration test
package. It is not a runtime dependency of the library.

## Installation

```swift
.package(
    url: "https://github.com/mikolaj92/OpenAPITransportKit.git",
    branch: "main"
)
```

```swift
.product(
    name: "OpenAPITransportKit",
    package: "swift-openapi-transport-kit"
)
```

Use the umbrella product first. Use split products later if a package needs a
narrower dependency surface.

## Modules

- `OpenAPITransportKit`: umbrella module.
- `OpenAPITransportKitCore`: provider adapter, multiplexing transport, source
  selection primitives.
- `OpenAPITransportKitFixtures`: operationId-based fixture responses.
- `OpenAPITransportKitReplay`: replay stores, request fingerprinting, and
  recording middleware.
- `OpenAPITransportKitDynamic`: closure-based dynamic responses.
- `OpenAPITransportKitStateful`: actor-backed stateful response providers.

## Response Sources

### Fixtures

```swift
import OpenAPITransportKit

let transport = FixtureTransport(
    loader: MemoryFixtureLoader(fixtures: [
        "getDashboard.success.json": FixturePayload(
            string: #"{"items":[]}"#
        )
    ])
)

let client = Client(
    serverURL: URL(string: "https://example.com")!,
    transport: transport
)
```

Fixture lookup is based on OpenAPI `operationId`, not URL.

Default fixture names:

```text
<operationId>.<scenario>.json
getDashboard.success.json
getDashboard.empty.json
getDashboard.error.json
```

Fixture sidecar metadata:

```text
getDashboard.success.json
getDashboard.success.meta.json
```

```json
{
  "status": 202,
  "headers": {
    "Content-Type": "application/json"
  }
}
```

Use `headerFields` for repeated headers:

```json
{
  "headerFields": [
    { "name": "Set-Cookie", "value": "a=1" },
    { "name": "Set-Cookie", "value": "b=2" }
  ]
}
```

### Dynamic

```swift
let transport = DynamicTransport { context in
    TransportResponse(
        status: .ok,
        body: HTTPBody(#"{"ok":true}"#)
    )
}
```

### Replay

```swift
let store = FileReplayStore(rootDirectory: replayDirectory)
let keyStrategy = FingerprintedReplayKeyStrategy(
    fingerprinter: StableRequestFingerprinter(
        includedHeaderNames: ["Accept", "X-Scenario"]
    )
)

let transport = ReplayTransport(
    store: store,
    keyStrategy: keyStrategy
)
```

### Recording

Recording is middleware because it observes a live transport response.

```swift
let recorder = RecordingClientMiddleware(
    writer: FileReplayStore(rootDirectory: replayDirectory),
    keyStrategy: OperationIDReplayKeyStrategy()
)

let client = Client(
    serverURL: URL(string: "https://example.com")!,
    transport: liveTransport,
    middlewares: [recorder]
)
```

### Source Switching

OpenAPITransportKit does not include a live HTTP transport. Pass any existing
`ClientTransport` as `live`.

```swift
let selectedSource: @Sendable () -> TransportSource = {
    .fixtures
}

let transport = MultiplexingTransport(
    selector: SourceSwitchingTransportSelector(
        sourceProvider: ClosureTransportSourceProvider { _ in selectedSource() },
        registry: TransportSourceRegistry(
            live: liveTransport,
            fixtures: fixtureTransport,
            replay: replayTransport,
            dynamic: dynamicTransport
        )
    )
)
```

Built-in sources are typed:

```swift
TransportSource.live
TransportSource.fixtures
TransportSource.replay
TransportSource.dynamic
TransportSource.stateful
```

Custom selection logic belongs in a user-defined `TransportSelector`.

## Validation

Tests use Swift Testing only.

```console
swift test
swift test --package-path IntegrationTests/GeneratedClient
swift build -c release
swift test -c release
swift test -c release --package-path IntegrationTests/GeneratedClient
```

The generated-client integration package runs `swift-openapi-generator` against
`openapi.yaml` and verifies the real generated `Client` pipeline:

- request serialization reaches the transport as `HTTPRequest`;
- `operationID` reaches the response provider;
- JSON responses deserialize into generated DTOs;
- generated status-code handling works for success and error responses.

## Compatibility

The package is designed for Swift Multiplatform:

- iOS
- macOS
- Linux
- Android Swift SDK

No SwiftUI, UIKit, AppKit, Vapor, TCA, or platform-specific runtime APIs are
required by the transport kit modules.
